# BLE Activity 协议

PaperMono 是 Central，主机是 Peripheral。服务 UUID 为 `E7D6D101-5A2D-4B7A-9C0E-123456789ABC`，只读 Activity 特征为 `E7D6D10A-5A2D-4B7A-9C0E-123456789ABC`。

现有 Mac Hub 广播本地名称 `StackChanCodex`；固件也接受服务 UUID 匹配。UUID/名称是服务发现标识，不能作为主机身份认证。主动扫描 5 秒，连接后请求 MTU 185、主动 `secureConnection()`，然后发现特征并读取。成功后间隔一小时，失败后一分钟重试；断开后 `deinit(false)`，不永久释放后续重试需要的控制器内存。

## 二进制布局

所有双字节整数均为 little-endian，无字符串终止符。

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 1 | magic `0xA7` |
| 1 | 1 | 版本 `2` 或 `3` |
| 2 | 1 | 天数 N，范围 1–112 |
| 3 | 1 | 第一天星期，Sunday=0…Saturday=6 |
| 4 | 1 | N 天窗口内活跃天数 |
| 5 | 1 | 当前连续天数 |
| 6 | 1 | 最长连续天数 |
| 7 | 1 | 保留，主机发 0 |
| 8 | 2 | 窗口内 turns 总计，饱和到 65535 |
| 10 | 2 | 窗口内分钟总计，饱和到 65535 |
| 12 | 2 | 活动结束日期：年 |
| 14 | 1 | 活动结束日期：月 |
| 15 | 1 | 活动结束日期：日 |
| 16 | 2 | **仅 v3**：主机本地时钟年 |
| 18 | 1 | **仅 v3**：本地时钟月 |
| 19 | 1 | **仅 v3**：本地时钟日 |
| 20 | 1 | **仅 v3**：小时，0–23 |
| 21 | 1 | **仅 v3**：分钟，0–59 |
| 22 | 1 | **仅 v3**：秒，0–59 |
| H | N | 每日打包值，按日期从早到晚 |
| H+N | 2 | 前面所有字节的 CRC16-CCITT-FALSE，小端 |

v2 的 H=16，总长 N+18；v3 的 H=23，总长 N+25。112 天分别是 **130** 和 **137** 字节。结束日期与 v3 校时时刻是两个独立字段，不能混用。

CRC 参数：poly=`0x1021`、init=`0xFFFF`、refin=false、refout=false、xorout=0。校验值 `CRC("123456789") = 0x29B1`；线上按低字节、高字节发送。CRC 只检测损坏，不认证发送者。

每个每日值：`(min(turns, 31) << 3) | level`。低 3 位为 level（主机范围 0–4）；高 5 位为饱和后的 turns。汇总 turns 单独保存，因此可大于每日饱和值之和。现有主机的等级定义：

| 当日 turns | level |
| --- | --- |
| 0 | 0 |
| 1 | 1 |
| 2–3 | 2 |
| 4–6 | 3 |
| ≥7 | 4 |

level 不表示账号额度或 token 消耗。固件把日期与窗口结束日做天数差映射，窗口之外无填色；今天始终省略活动填色。

## 校时与刷新

v3 使用主机本地公历时间，不是 UTC epoch，也不携带时区偏移。主机应使用正确时区和公历；固件写入 RX8130CE 后离线继续走时。需要固定中国标准时间时，在主机选择 Asia/Shanghai，不能简单再给本地小时加 8。

固件仅在包头、长度、日期和 CRC 校验通过后写入 RTC；写入返回结果目前没有独立确认。仅分钟改变会使时间重绘，日期改变触发完整日历更新。时钟字段不参与活动数据比较，不会因秒不同就刷新整个月历。

版本兼容：本固件接受 v2/v3；早期只支持 v2 的固件不能读取 v3，主机与设备应协同升级。v3 的 RTC 硬件验收状态见 [验证记录](verification.md)。

## 主机响应要求与已知限制

- 保持二进制长度，不能按 C 字符串截断零字节。
- 支持 GATT 长读取与 `offset`；错误偏移返回 invalid offset。
- **同一次读取的所有分片须使用同一快照**。v3 的时间会变化，不能在每个 offset 重建时间和 CRC。现有 Hub 参考实现仍逐次生成 payload，跨秒长读取的一致性有待加固。
- 0 天或年份为 0 的占位包会被拒绝。主机应先加载活动数据，再提供有效响应。
- 固件目前只检查星期 0–6、日期范围、大小和 CRC，未穷举检查所有汇总计数/level 一致性；不要把 CRC 通过等同于完整语义校验。

## 安全与隐私

经所有者明确接受风险，当前 Hub 的 Activity 特征为 `.readable`，不要求 `.readEncryptionRequired`。PaperMono 自己仍请求加密/Just Works 配对，但其他附近客户端可能直接读取活动等级、轮次、连续天数和 v3 本地时间；这不提供主机端访问控制，也无 MITM 身份校验保证。

包中不包含提示词、回答、任务标题或账号令牌。仍应把活动规律视为个人数据，在可信环境使用；需要访问控制时，应在主机恢复经验证的加密/授权方案。本仓库不携带用户配对记录或实际数据包。
