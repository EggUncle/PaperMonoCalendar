# 排障

先确认设备为 PaperMono C153、供电稳定、运行当前固件、Hub 已注册 BLE 服务。不要反复烧录或整片擦除来代替分阶段诊断；墨水屏断电后仍会保留旧画面。

| 顶部状态 | 能确认的范围 / 下一步 |
| --- | --- |
| WAITING | 初始画面；未证明应用主循环或 BLE 同步已完成 |
| SCANNING | 首次扫描前的状态标记；也可能保留自之前的运行，不能仅据此判定栈死锁 |
| NOT FOUND | 本次扫描没有匹配服务 UUID 或名称；检查 Hub 运行状态、广播、距离 |
| LINK FAIL | 找到广播但连接未成功 |
| AUTH FAIL | 主动安全连接返回失败；检查配对状态，不要直接清空整个 NVS |
| NO SERVICE | 已连接，但没有预期服务 UUID |
| NO DATA | 未找到可读 Activity 特征；不是“活动为零” |
| BAD DATA | 读取后解码失败，也可能读到空值；不证明主机回调收到过请求，更不证明是 CRC 单一原因 |
| SYNCED | 一次活动包校验通过；若该包是 v2，不代表已经校时；也不表示 BLE 当前持续连接 |

## 没有日期底纹

确认 SYNCED、日期位于 112 天窗口、该日 level 非零。今天按设计保持白底并加矩形框。统计指标是任务轮次，不是消费金额；无需提高账号消费来“触发”底纹。

## 时间错误

- RTC 在掉电/首次初始化时可能回到编译时刻；编译时刻不是持续校时源。
- v3 主机需发送正确的本地公历时钟，并在固件验包后写入 RTC。
- v2 只同步活动，不同步时间。检查包版本，不要只看 SYNCED。
- USB 115200 仍有 `SET YYYY-MM-DD HH:MM:SS` 接口，但本机曾只观察到终端回显、未见固件确认，也未改变屏幕。必须看到设备 `RTC set:` 日志并核对屏幕，不能把终端输入回显当成功。
- RTC v3 自动校时仍待最终设备验收，见 [验证记录](verification.md)。

## 刷新明显

文字局刷累计十次后，下一次计划更新进行 quality 全刷；这种清理会闪动。启动和跨日也会全刷。当前 M5GFX 版本不等于完成 OTP 迁移，不承诺“完全不闪”；后续修改遵循 [REFRESH_POLICY](../REFRESH_POLICY.md)。

首次 SCANNING 与最终状态可能各推送一次；不变的失败重试不触发重绘。先查看日志中的 `Display refresh` 类型/次数，再判断是预定清理、状态变化、反复重启还是底层刷新问题。

## 构建 / 串口

找不到 CLI 时安装 Arduino CLI 或设置 ARDUINO_CLI。使用 `sh tools/setup.sh` 安装固定版本；它会写入 CLI 的配置数据目录，请留意其他项目共享的依赖。

上传前先 `arduino-cli board list`，串口可能随插拔变化。若提示占用，关闭正在使用该端口的监视器。上传不会替你编译；先确认 `build/` 是本次源码产物。未知固件请先备份。
